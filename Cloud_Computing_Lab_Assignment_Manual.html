ASSIGNMENT 01: VIRTUALBOX HYPERVISOR & VIRTUAL MACHINE MANAGEMENT

1.1 Aim & Objective

To install, configure, and operate Oracle VM VirtualBox (Type-2 Hosted Hypervisor) on a Windows host machine, allocate virtual compute resources (CPU, RAM, Hard Disk), and provision a guest Linux virtual machine (Ubuntu 22.04 LTS).

1.2 Theoretical Concepts

Virtualization is the foundational technology of Cloud Computing. It abstracts physical computer hardware (processors, memory, storage) into multiple isolated computing environments called Virtual Machines (VMs).

  • Type-1 Hypervisor (Bare-Metal): Runs directly on hardware (e.g., VMware ESXi, Xen, KVM). Used in enterprise cloud data centers (AWS Nitro).
  • Type-2 Hypervisor (Hosted): Runs as software on an existing host operating system (e.g., Oracle VirtualBox on Windows 11). Ideal for student laboratories and software development.

1.3 Step-by-Step Practical Implementation

  1. Download and Installation: Execute VirtualBox-7.2-Setup.exe on the host Windows machine. Enable VirtualBox Networking and VirtualBox USB support.
  2. Virtual Machine Creation: Open VirtualBox Manager. Click New. Name: Ubuntu-22.04-LTS-Server, Type: Linux, Version: Ubuntu (64-bit).
  3. Hardware Resource Allocation: Allocate 2048 MB RAM (Base Memory) and 2 vCPUs. Enable EFI if required.
  4. Virtual Storage Setup: Create a Virtual Hard Disk using VDI (VirtualBox Disk Image) format with a dynamically allocated size of 25.00 GB.
  5. VirtualBox CLI Execution (VBoxManage): 
    # Create and register virtual machine via command line
VBoxManage createvm --name "Ubuntu-22.04-LTS-Server" --ostype "Ubuntu_64" --register
VBoxManage modifyvm "Ubuntu-22.04-LTS-Server" --memory 2048 --cpus 2 --vram 16
VBoxManage createmedium disk --filename "C:Users
ikitaVirtualBox VMsUbuntu.vdi" --size 25000
VBoxManage storagectl "Ubuntu-22.04-LTS-Server" --name "SATA" --add sata --controller IntelAhci
VBoxManage storageattach "Ubuntu-22.04-LTS-Server" --storagectl "SATA" --port 0 --device 0 --type hdd --medium "C:Users
ikitaVirtualBox VMsUbuntu.vdi"
VBoxManage startvm "Ubuntu-22.04-LTS-Server" --type gui

1.4 Result & Verification

Oracle VirtualBox 7.2 was successfully deployed. The virtual machine booted into the Ubuntu installation environment with 2048 MB RAM and 2 vCPUs safely compartmentalized from the host Windows OS.

Viva Question 1: What is the main difference between Type-1 and Type-2 Hypervisors?

Type-1 hypervisors interface directly with physical CPU and memory without an underlying OS, providing higher performance. Type-2 hypervisors execute on top of an existing OS (Windows/macOS), which incurs a slight virtualization overhead but provides easy GUI management.

2.2 Theoretical Concepts

Amazon Elastic Compute Cloud (EC2) provides resizable compute capacity in the cloud. It eliminates upfront hardware investment. Key EC2 abstractions include:

ASSIGNMENT 03: AWS EBS (ELASTIC BLOCK STORE) STORAGE

3.1 Aim & Objective

To create a high-performance Amazon EBS block storage volume, attach it to a running EC2 instance in the same Availability Zone, initialize an ext4 filesystem, mount it to the Linux OS directory tree, and capture an incremental snapshot backup.

3.2 Theoretical Concepts

Amazon EBS delivers raw, persistent, unformatted block-level storage volumes designed to behave like physical hard drives connected to an EC2 instance. Unlike instance store volumes (ephemeral), data stored on an EBS volume persists independently of the instance lifecycle.

  • gp3 (General Purpose SSD): Baseline 3,000 IOPS and 125 MB/s throughput; price-performance leader.
  • io2 (Provisioned IOPS SSD): Sub-millisecond latency for heavy transactional I/O.
  • Snapshots: Point-in-time, incremental backups stored durably in Amazon S3.

3.3 Implementation & CLI Commands

# 1. Create a 50 GiB gp3 EBS volume in us-east-1a
aws ec2 create-volume --availability-zone us-east-1a --size 50 --volume-type gp3 --tag-specifications 'ResourceType=volume,Tags=[{Key=Name,Value=DAVV-Data-Volume}]'

# 2. Attach volume to EC2 instance
aws ec2 attach-volume --volume-id vol-0f9e8d7c6b5a41122 --instance-id i-0a8b9c7d1e2f3456a --device /dev/xvdf

# 3. SSH into instance and configure Linux filesystem
lsblk                                          # List block devices
sudo mkfs -t ext4 /dev/xvdf                    # Format with ext4
sudo mkdir /mnt/davv_data                      # Create mount point
sudo mount /dev/xvdf /mnt/davv_data            # Mount volume
df -h /mnt/davv_data                           # Verify 50 GiB mounted space

# 4. Create an EBS Snapshot
aws ec2 create-snapshot --volume-id vol-0f9e8d7c6b5a41122 --description "Pre-upgrade backup of /mnt/davv_data"

3.4 Result & Verification

The 50 GiB gp3 volume vol-0f9e8d7c6b5a41122 was attached to device /dev/xvdf, formatted with ext4, and mounted at /mnt/davv_data. Snapshot snap-0487ab19cd23ef reached 100% completed state.

Viva Question 3: Can an EBS volume be attached to EC2 instances across different Availability Zones?

No. Standard EBS volumes are tied to a specific Availability Zone (AZ) to ensure ultra-low network latency. To move data to another AZ, create an EBS snapshot and restore a new volume in the destination AZ.

ASSIGNMENT 05: AWS ELB (ELASTIC LOAD BALANCER)

5.1 Aim & Objective

To configure an AWS Application Load Balancer (ALB), establish a Target Group spanning multiple Availability Zones, configure periodic HTTP health checks, and verify dynamic Round-Robin traffic distribution.

5.2 Theoretical Concepts

Elastic Load Balancing automatically distributes incoming application traffic across multiple targets, such as EC2 instances in multiple Availability Zones, increasing fault tolerance and availability.

  • Application Load Balancer (ALB): Operates at Layer 7 (HTTP/HTTPS). Routes traffic based on content (host header, URL path like /api or /images).
  • Target Group: Logical grouping of backend targets evaluated by health checks.
  • Health Checks: Periodic HTTP requests (e.g., GET /health). If an instance fails 2 consecutive checks, the ALB stops routing traffic to it.

5.3 Implementation & CLI Commands

# 1. Create Target Group for HTTP Port 80
aws elbv2 create-target-group     --name tg-web-production     --protocol HTTP     --port 80     --vpc-id vpc-0198273645aabbcc     --health-check-path /health     --health-check-interval-seconds 30

# 2. Register EC2 instances to Target Group
aws elbv2 register-targets --target-group-arn <TG_ARN>     --targets Id=i-0a8b9c7d1e2f3456a Id=i-0f9e8d7c6b5a4321b

# 3. Create Application Load Balancer
aws elbv2 create-load-balancer     --name SCSIT-Production-ALB     --subnets subnet-01public subnet-02public     --security-groups sg-01a2b3c4

# 4. Create Listener forwarding to Target Group
aws elbv2 create-listener --load-balancer-arn <ALB_ARN>     --protocol HTTP --port 80     --default-actions Type=forward,TargetGroupArn=<TG_ARN>

5.4 Result & Verification

Requests dispatched to scsit-alb-198273645.us-east-1.elb.amazonaws.com were distributed evenly between i-0a8b9c7d1e2f3456a (AZ us-east-1a) and i-0f9e8d7c6b5a4321b (AZ us-east-1b) in Round-Robin sequence with 100% target health.

Viva Question 5: What is the difference between ALB and NLB?

ALB operates at Layer 7 (Application) and inspects HTTP headers, cookies, and URLs for path-based routing. NLB operates at Layer 4 (Transport), routing TCP/UDP traffic with extreme speed and ultra-low latency for millions of connections.

ASSIGNMENT 06: AWS AUTO SCALING GROUP (ASG)

6.1 Aim & Objective

To establish an AWS Auto Scaling Group (ASG) using Launch Templates, configure Target Tracking scaling policies based on CloudWatch CPU metrics (> 70%), and test dynamic horizontal Scale-Out and Scale-In.

6.2 Theoretical Concepts

Auto Scaling ensures that the application has the right number of EC2 instances available to handle load spikes efficiently while cutting costs during quiet periods. Core components include:

  • Launch Template: Defines instance AMI, type, key pair, security groups, and user-data.
  • Capacity Specifications: Minimum (2), Desired (2), and Maximum (6) instances.
  • Target Tracking Policy: Automatically adds or removes instances to keep a metric (such as average CPU utilization) at a specified target (e.g., 70%).
  • Cooldown Period: Time period (e.g., 300s) during which ASG does not launch or terminate additional instances, allowing metric stabilization.

6.3 Implementation & CLI Commands

# 1. Create Launch Template
aws ec2 create-launch-template --launch-template-name lt-web-tier-v2     --launch-template-data '{"ImageId":"ami-0c7217cdde317cfec","InstanceType":"t2.micro","SecurityGroupIds":["sg-01a2b3c4"]}'

# 2. Create Auto Scaling Group
aws autoscaling create-auto-scaling-group     --auto-scaling-group-name asg-web-tier-autoscaling     --launch-template LaunchTemplateName=lt-web-tier-v2     --min-size 2 --max-size 6 --desired-capacity 2     --vpc-zone-identifier "subnet-01public,subnet-02public"     --target-group-arns <TG_ARN>

# 3. Configure Target Tracking Scaling Policy (Average CPU = 70%)
aws autoscaling put-scaling-policy --auto-scaling-group-name asg-web-tier-autoscaling     --policy-name cpu70-target-tracking --policy-type TargetTrackingScaling     --target-tracking-configuration '{"PredefinedMetricSpecification":{"PredefinedMetricType":"ASGAverageCPUUtilization"},"TargetValue":70.0}'

6.4 Result & Verification

Simulating an 85% CPU load spike triggered the Target Tracking policy, causing ASG to automatically launch a 3rd instance, registering it with the ELB target group within 180 seconds. As load normalized, capacity scaled back in to 2 instances.

Viva Question 6: What is the purpose of an Auto Scaling Cooldown period?

The cooldown period prevents the ASG from launching or terminating additional instances before the previous scaling activity has taken effect and application metrics have had time to stabilize.

ASSIGNMENT 07: AWS CLOUDWATCH MONITORING & ALARMS

7.1 Aim & Objective

To monitor AWS infrastructure metrics using Amazon CloudWatch, establish threshold-based Alarms for CPUUtilization (> 70%), and automate email/SMS alert dispatch via Amazon Simple Notification Service (SNS).

7.2 Theoretical Concepts

Amazon CloudWatch provides real-time monitoring of AWS resources and customer applications. It collects metrics, monitors log files, and sets alarms.

  • Metrics: Time-ordered data points (e.g., CPUUtilization, NetworkIn, DiskReadOps).
  • Alarms: Watches a single metric over a specified period. Evaluates three states: OK, ALARM, and INSUFFICIENT_DATA.
  • SNS Integration: Publishes notifications to email/SMS subscribers or triggers auto-remediation Lambda functions upon state transitions.

7.3 Implementation & CLI Commands

# 1. Create SNS Topic for Cloud Alerts
TOPIC_ARN=$(aws sns create-topic --name SCSIT-Lab-Alerts --query 'TopicArn' --output text)

# 2. Subscribe student email to SNS topic
aws sns subscribe --topic-arn $TOPIC_ARN --protocol email --notification-endpoint nikita.negi@davv.ac.in

# 3. Create CloudWatch Metric Alarm for High CPU
aws cloudwatch put-metric-alarm     --alarm-name "High-CPU-Utilization-Alarm"     --metric-name CPUUtilization     --namespace AWS/EC2     --statistic Average     --period 300     --threshold 70.0     --comparison-operator GreaterThanThreshold     --dimensions Name=AutoScalingGroupName,Value=asg-web-tier-autoscaling     --evaluation-periods 2     --alarm-actions $TOPIC_ARN

7.4 Result & Verification

CloudWatch successfully tracked CPU utilization data points. Injecting stress into the cluster caused the alarm state to transition from OK to ALARM, firing an automated SNS notification payload to the administrator.

Viva Question 7: What are the three states of a CloudWatch Alarm?

1. OK: Metric is within defined threshold bounds.
2. ALARM: Metric has breached the defined threshold for the evaluation periods.
3. INSUFFICIENT_DATA: Not enough data points collected to determine alarm status.

9.2 Theoretical Concepts

AWS IAM controls authentication (who can sign in) and authorization (what permissions they have). Key constructs include:

ASSIGNMENT 11: AMAZON VPC (VIRTUAL PRIVATE CLOUD) & VPN

11.1 Aim & Objective

To design an isolated Amazon Virtual Private Cloud (VPC) with a 10.0.0.0/16 CIDR block, partition public and private subnets across multiple AZs, configure an Internet Gateway (IGW) and NAT Gateway, and configure a simulated Site-to-Site IPsec VPN connection.

11.2 Theoretical Concepts

Amazon VPC is a logically isolated virtual network dedicated to your AWS account. It mirrors a traditional physical network with cloud scalability.

  • CIDR (Classless Inter-Domain Routing): Defines the IP address block (e.g., 10.0.0.0/16 = 65,536 private IP addresses).
  • Public Subnet: Routes traffic directly out to an Internet Gateway (IGW) via 0.0.0.0/0. Hosts web servers & load balancers.
  • Private Subnet: Has no direct route to the IGW. Reaches the internet outbound via a NAT Gateway located in the public subnet. Protects database tiers.
  • Site-to-Site VPN: Connects on-premises university data centers to AWS via encrypted IPsec tunnels.

11.3 Subnet Topology & CLI Commands

# 1. Create VPC
VPC_ID=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 --query 'Vpc.VpcId' --output text)

# 2. Create Public Subnet (10.0.1.0/24) and Private Subnet (10.0.3.0/24)
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.1.0/24 --availability-zone us-east-1a
aws ec2 create-subnet --vpc-id $VPC_ID --cidr-block 10.0.3.0/24 --availability-zone us-east-1a

# 3. Attach Internet Gateway (IGW) to VPC
IGW_ID=$(aws ec2 create-internet-gateway --query 'InternetGateway.InternetGatewayId' --output text)
aws ec2 attach-internet-gateway --vpc-id $VPC_ID --internet-gateway-id $IGW_ID

# 4. Create Public Route Table (0.0.0.0/0 -> IGW)
RT_PUB=$(aws ec2 create-route-table --vpc-id $VPC_ID --query 'RouteTable.RouteTableId' --output text)
aws ec2 create-route --route-table-id $RT_PUB --destination-cidr-block 0.0.0.0/0 --gateway-id $IGW_ID

11.4 Result & Verification

VPC vpc-0198273645aabbcc was created with 4 subnets spanning 2 AZs. Web traffic flowed freely through public subnets, while database nodes in private subnets remained protected from direct incoming internet probes.

Viva Question 11: What is the purpose of a NAT Gateway in a VPC?

A Network Address Translation (NAT) Gateway allows EC2 instances in a private subnet to make outbound connections to the internet (for software updates or patches) while preventing the internet from establishing inbound connections to those instances.

13.1 Aim & Objective

To author, deploy, and invoke an event-driven AWS Lambda serverless function in Node.js 20.x, configure automated S3 ObjectCreated triggers, inspect execution logs in CloudWatch, and analyze serverless billing metrics.

13.2 Theoretical Concepts

Serverless Computing enables developers to execute code in response to events without provisioning or managing physical or virtual servers. AWS automatically manages capacity, patching, and horizontal scaling. Billing is strictly metered per millisecond of compute execution.

13.3 Serverless Lambda Handler Code (index.js)

exports.handler = async (event, context) => {
  // Extract bucket and object key from event payload
  const bucket = event.Records?.[0]?.s3?.bucket?.name || "test-bucket";
  const key = event.Records?.[0]?.s3?.object?.key || "assignment.pdf";

  console.log("[LAMBDA EXECUTION] Processing upload: s3://" + bucket + "/" + key);
  console.log("[REQUEST ID] " + context.awsRequestId);

  const responseBody = {
    statusCode: 200,
    body: JSON.stringify({
      message: "Serverless image thumbnail generated successfully!",
      originalFile: key,
      thumbnailDestination: "thumbnails/" + key,
      processedAt: new Date().toISOString(),
      student: "Nikita Negi (Roll No: 2211229)",
      institution: "SCSIT DAVV Indore"
    })
  };

  return responseBody;
};

Viva Question 13: What is a Lambda "Cold Start", and how can it be mitigated?

A cold start is the initialization delay that occurs when a serverless function is invoked for the first time or after a period of inactivity, as AWS provisions a new container sandbox and loads runtime dependencies. It can be mitigated using AWS Lambda Provisioned Concurrency or by keeping bundle sizes lightweight.
